# Тестовое задание: пагинация списка

Это урезанный проект на нашем реальном стеке (React + TypeScript + SCSS, сборка на gulp).
Из большого продукта вырезан один компонент — `PageSelector` — вместе с демо-стендом,
который его использует. Остальной код продукта в задании не участвует.

## Установка и запуск

1. `npm i`
2. `npm install -g gulp-cli` (если не установлен глобально)
3. `npm run dev` (или `gulp`) — поднимет dev-сервер на `http://localhost:8000` с автообновлением

## Структура

- `src/App/components/PageSelector/PageSelector.tsx` — **основной файл задания**, его и нужно
  дорабатывать
- `src/App/App.tsx` — демо-стенд, который подаёт в `PageSelector` тестовые данные с имитацией
  сетевой задержки; менять не нужно (но можно смотреть, чтобы понять, как компонент вызывается)
- `src/UIKit/Loader`, `src/App/shared/types.ts` — вспомогательные зависимости компонента

Правьте только `PageSelector.tsx` (и `pageSelector.scss`, если для второй части понадобятся
стили). Публичный контракт пропсов компонента (что он принимает снаружи) менять нельзя.

## Задание 1. Поиск и исправление бага (~45–60 минут)

В компоненте пагинации списка взаимодействий два репорта от QA:

1. При быстром переключении между номерами страниц (кликнуть 2 → сразу 5) иногда после клика на
   страницу 5 в списке ненадолго или насовсем показываются данные другой страницы.
2. В консоли браузера появляется React-предупреждение про уникальные `key` при рендере номеров
   страниц.

*Демо-стенд ниже помогает воспроизвести баг 1: элементы в списке подписаны, с какой страницы они
пришли — можно наглядно увидеть рассинхронизацию с активной кнопкой страницы.*

Найдите причину каждой проблемы и исправьте, не меняя публичный контракт пропсов компонента.
Кратко (2–3 предложения на баг) опишите, почему это происходило.

---

## Задание 2. Доработка существующего кода (~60–90 минут)

Необходимо доработать пагинацию:

1. Добавить выбор размера страницы (10 / 20 / 50 элементов) вместо захардкоженного
   `PART_SIZE = 20`.
2. Добавить кнопки перехода «В начало» / «В конец» в дополнение к существующим стрелкам.
3. При смене размера страницы текущая позиция должна оставаться разумной (не выходить за
   пределы, не сбрасываться в 0 без необходимости).

Логика отображаемого окна номеров страниц (`getPagesParams`, эллипсисы слева/справа) должна
продолжать работать корректно при любом размере страницы.

текстовое объяснение к заданию 1.
